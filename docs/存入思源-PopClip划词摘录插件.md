# 存入思源：选中文字，一键收进思源笔记

> 记笔记最难的不是写，而是**打开笔记**。看到一句好话，等你切到思源、找到那篇文档、再粘贴回来，那个念头已经凉了。
>
> 「存入思源」是一个 macOS PopClip 扩展：在**任意 App** 里选中文字，点一下图标，内容就追加到思源里指定的文档。不打开思源、不弹窗、不打断当前操作。

---

## 它补上了哪一块

思源自带的网页剪藏扩展主要面向浏览器；而在 PDF、微信、Pages、邮件、终端里读到的一段话，往往只能靠复制 → 切换窗口 → 找到文档 → 粘贴。这个插件把中间那几步压成一次点击。

另一个特点是**写入方式**：它调用思源 3.7+ 内置的 `SiYuan-Kernel` 命令行，直接把内容追加成思源块，而不是往工作空间里扔一个 Markdown 文件。因此写入会被思源内核正常索引，块 ID、反向链接、搜索都能照常工作。

## 功能一览

| 能力 | 说明 |
|---|---|
| 任意 App 划词 | 只要能选中文字，PopClip 能弹出，插件就能用 |
| 列表化写入 | 无论单行多行都是**一个无序列表项**；正文按纯文本写入，不会被误解析成 Markdown 格式 |
| 来源不抢眼 | 来源缩进成**子列表项**（网页带标题与可点链接），不再是与正文平级的引用块 |
| PDF 硬换行合并 | 中文直连、英文补空格、行尾连字符还原断词；应用名、网址、文字断行特征三重识别，覆盖 Edge 内置 PDF 查看器 |
| 四种目标定位 | 文档 ID、笔记本 + 文档标题、今日日记、修饰键切换多场景 |
| 一个动作多个去处 | 按住 ⌥ / ⌘ / ⌃ 点图标，临时分流到不同文档，不用改设置 |
| 追加不覆盖 | 一律追加到文档末尾，不改动、不删除任何已有内容 |
| 明确反馈 | 成功打勾；失败抖动 X 并给出具体原因，配置问题自动弹出设置面板 |
| 干净 | 不改剪贴板、不申请辅助功能权限、不联网、不上传任何数据 |
| 无需 API Token | 不走 HTTP API，不用填 Token、端口，也不读取 `conf.json` |

## 写进笔记是什么样

```markdown
- 地方政府不只是"守夜人"，而是深度参与经济发展的"运动员"。
  - 15:32 · [置身事内 - 读书笔记](https://example.com/article) · Safari
```

整条摘录是**一个无序列表项**，来源是缩进一层的**子列表项**。相比与正文平级、带竖线的引用块，来源的从属关系更清楚，视觉上不再和正文抢位置；整条摘录还能在思源里折叠、拖动、加块引用。

实测块结构：`列表 l → 列表项 i → 段落 p`，来源再挂一层 `子 l → 子 i → 子 p`，是真正的嵌套块，不是靠空格假装缩进。

内容规则：

- **PDF 来源**（预览、PDF Expert、Acrobat、Zotero、网址含 `.pdf`，或文字呈现典型 PDF 硬断行）：复制出来的硬换行会智能合并成连续一句——中文直连、英文补空格、行尾连字符还原断词（`inter-` + `national` → `international`）、空行变一个空格。
- 浏览器内置 PDF 查看器常常拿不到网址、应用名也不含 PDF 字样，此时靠「识别 PDF 式断行」按文字形状兜底：多行、每行较短、句子被从中间截断、没有空行和列表 → 自动合并；网页诗歌或窄栏排版若被误合并，可在设置里关掉这一项。
- **网页等其他来源**：保留原有分行，但用行内换行留在同一个列表项块里，不会散成多个段落。
- 正文按纯文本写入，原文里的 `*`、行首 `- ` 等 Markdown 标记会被转义，避免被思源误解析；来源行的链接仍可点击。
- 浏览器来源带网页标题与链接；PDF、微信、Pages 等拿不到 URL 时降级为 `15:32 · 预览`。
- 「保留来源信息」关掉后只剩正文列表项；时间格式可选 `15:32`、`2026-11-04 15:32` 或不显示。
- 遇到没被识别出来的 PDF 阅读器，可在「PDF 应用白名单」补一行 App 名关键词，或临时打开「总是合并换行」。

## 为什么不需要 API Token

这是这个插件最值得说的一点。

思源从 3.7 起内置了命令行 `SiYuan-Kernel`（macOS 下位于 `/Applications/SiYuan.app/Contents/Resources/kernel/SiYuan-Kernel`）。它是**本地进程直接访问工作空间数据**，调用的是内核的数据层，不经过 HTTP 服务，因此 `Authorization: Token ...` 这一层根本不存在：

```
选中文本 → PopClip → send.py → SiYuan-Kernel block append --parent <文档ID> --file - → 思源
```

对比一下：走 HTTP 内核 API（`127.0.0.1:6806`）就必须带 API Token。实测在无 Token 的情况下调用 `lsNotebooks` 会返回 `Auth failed [session]`，而且思源内核会对连续失败的鉴权做限流。CLI 路径把这些都绕开了——不需要 Token、不需要端口、不需要内核 HTTP 服务，日记路径也由思源自己按「设置 → 外观 → 日记」解析，永远和你的设置一致。

**安全边界说清楚**：CLI 绕过 HTTP 鉴权，靠的是 macOS 账户的文件系统权限——任何能在你账户下运行该二进制的本地进程都能写笔记。这是思源 CLI 自身的信任模型，不是插件引入的新风险。反过来，插件里不会保存任何 Token，也不会有鉴权失败锁死内核的问题。

实测环境：思源 3.8.8 + PopClip 2026.8.1 + macOS。CLI 写入后，**正在运行的思源内核可以立即查到新块**（通过只读 SQL 验证），所以「思源开着时直接写工作空间」这条路是通的。

## 环境要求与安装

| 项 | 要求 |
|---|---|
| 系统 | macOS（PopClip 是 macOS 专属） |
| 思源笔记 | 3.7 及以上（需要内置 CLI） |
| PopClip | 2026.8.1 上验证过，较新版本均可 |
| Python | 系统自带 `/usr/bin/python3`（需 Xcode Command Line Tools） |

安装三步：

1. 双击 `SiYuan Clipper.popclipextz` 安装。
2. 首次会弹「未签名扩展」警告，点一次确认即可。想永久免弹，在终端执行一次并重启 PopClip：

   ```bash
   defaults write com.pilotmoon.popclip LoadUnsignedExtensions -bool YES
   ```

3. 在 PopClip 设置里做**一次**配置，之后就不用再管了。

> 出现未签名警告是因为这是自制扩展且包含 Shell Script action，属于 PopClip 的正常行为。插件源码只有 `Config.yaml` + `send.py` 两个文件，可以直接打开审阅。

## 快速上手

**方式 A（零配置，推荐先试）**：把「默认定位方式」改成 `今日日记`，装好即用，连文档 ID 都不用填。

**方式 B**：保持 `文档 ID`，在「默认文档 ID」填目标文档的块 ID。获取方式：

- 思源界面：打开文档 → 点文档标题前的块标 → 复制 → 复制块 ID；
- 命令行：

  ```bash
  /Applications/SiYuan.app/Contents/Resources/kernel/SiYuan-Kernel \
    sql "SELECT id, hpath FROM blocks WHERE type='d' AND content='文档标题' LIMIT 5" \
    -w "<你的工作空间路径>" -f json
  ```

「CLI 路径」和「Workspace 路径」都留空即可自动探测。插件会显式传 `-w`，因为 CLI 默认会猜到 `~/SiYuan`，而实际工作空间往往在别处。

## 四种目标定位方式

| 方式 | 适合 | 说明 |
|---|---|---|
| 文档 ID | 长期固定的收集箱 | 一次配置，最快最稳 |
| 笔记本 + 文档标题/路径 | 不想记 ID | 用只读 SQL 查文档 ID；建议写全 `笔记本/文档标题` 避免同名歧义 |
| 今日日记 | 流水式摘录 | 调用 `dailynote create`，思源自己解析日记路径；已存在则直接追加 |
| 修饰键切换场景 | 需要分流 | 见下一节 |

## 场景：一个动作，多个去处

在设置页的「场景配置」多行文本框里，一行一个去处：

```
⌥ | 读书摘录 | id:20210808180117-abc1234
⌘ | 灵感收集 | path:我的笔记本/灵感收集
⌃ | 今日日记 | daily:我的笔记本
```

格式是 `修饰键 | 名称 | 目标`：

- **修饰键**：`⌥` / `⌘` / `⌃` / `⇧`，也可写 `option` / `command` / `control` / `shift`。`#` 开头是注释行。
- **名称**：只是显示标签，出现在成功通知和日志里（「已存入：读书摘录」），**不影响写到哪**。
- **目标**：`id:文档ID`、`path:笔记本/文档标题`、`daily:笔记本名`（`daily` 后留空则用第一个可用笔记本）。

不按修饰键时写入「默认目标」；按了键但没匹配到场景，也会回落到默认目标，不会失败。同时按住多个键时，按配置从上往下取第一个匹配的行。留空 = 禁用场景，插件照常工作。

想确认修饰键有没有生效，可以打开「成功时发送通知」，通知里会显示目标名称；或查看 `~/Library/Logs/PopClip-Siyuan.log`。

## 反馈与排错

| 情况 | 表现 |
|---|---|
| 成功 | PopClip 显示对勾；可选额外系统通知 |
| 配置问题 | 抖动 X + 具体原因 + 自动弹出设置面板 |
| 命令失败 / 超时 / 内核报错 | 抖动 X + 具体原因 |

失败原因会区分「找不到 CLI」「Workspace 无效」「文档 ID 无效」「找不到文档」「匹配到多个同名文档」「命令超时」等，不会只给一个笼统的失败图标。详细日志在 `~/Library/Logs/PopClip-Siyuan.log`。

## 常见问题

**和思源官方网页剪藏扩展有什么区别？**
官方剪藏面向浏览器网页，能存整页、图片等；这个插件是系统级划词，覆盖浏览器之外的 App（PDF、微信、Pages、终端……），更轻，只做「把选中的文字追加到指定文档」这一件事。

**和「乔木闪记 Jot」有什么区别？**
产品思路来自它（重视原文、单独标注来源、场景化去处、明确的能力边界），但实现完全不同：乔木闪记是独立菜单栏 App，靠辅助功能权限读选中内容，直接写 Markdown 文件到 Obsidian 或普通文件夹，支持截图和 OCR；这个插件是 PopClip 的一个划词动作，走思源内置 CLI 写块，不做截图、OCR、文件管理，写入结构也改成了嵌套列表。

**为什么改成列表，而不是普通段落？**
把「摘录 + 出处」做成一个列表项和它的子项，来源缩进后不再和正文平级，可读性更好，整条摘录也能在思源里折叠、拖动、加块引用。多行内容仍留在同一个列表项块内，不会被拆散。

**PDF 里复制出来的文字断行怎么处理？**
默认智能合并成连续一句：中文直连、英文补空格、行尾连字符还原断词、空行变一个空格。识别走三条线：应用名 / Bundle ID 关键词、网页 URL 里的 `.pdf`、以及**文字本身的断行特征**（多行、每行较短、句子被从中间截断且无空行列表）。第三条不依赖应用和网址，专门覆盖 Edge 等浏览器内置 PDF 查看器——PopClip 对这类浏览器未必提供网页 URL，仅靠前两条会漏判。若网页诗歌、窄栏排版被误合并，关掉「识别 PDF 式断行」即可；也可在「PDF 应用白名单」补 App 关键词，或临时打开「总是合并换行」。网页来源默认保留分行。

**会覆盖或修改已有笔记吗？**
不会。只用 `block append` 追加到文档末尾，不覆盖、不删除、不重命名。撤销请用思源内的 ⌘Z。

**需要 API Token 吗？**
不需要，配置面板里也没有这一项。详见上文「为什么不需要 API Token」。

**思源没开着能用吗？**
CLI 官方说明无需运行 HTTP server，但本插件只在思源 App 运行的状态下验证过，建议保持思源开启。另外思源 3.7 以下没有内置 CLI，插件无法工作。

**支持加密笔记本吗？**
不支持，思源 CLI 官方明确不支持加密笔记本。

**Windows / Linux 能用吗？**
不能，PopClip 只存在于 macOS。思源 CLI 本身是跨平台的，思路可以借鉴。

**写入后思源界面没立刻看到？**
数据层已验证：运行中的内核可以立即查到新块。但前端界面是否需要切走再切回或手动刷新，作者还没法替每个人确认，欢迎反馈你的实际表现。

**会上传我的笔记内容吗？**
不会。插件只在本机调用 `SiYuan-Kernel`，没有任何网络请求，也不读取或保存 API Token。

## 明确不做

截图 / 图片 / 文件 / OCR · PDF 页码与电子书书名作者 · 代码语言识别 · 剪贴板接管与模拟 ⌘C · 撤销上一条 · 全文搜索与管理笔记 · 同步 · 自定义弹窗界面 · 任何联网上传。

它不是笔记管理器，也不是同步工具，只负责把一段选中的文字快速放进思源。

## 实现简介

包内只有三个文件：

```
SiYuan Clipper.popclipext/
├── Config.yaml   # 扩展定义与 15 项设置（官方推荐的新式 YAML 配置）
├── send.py       # 主逻辑，Python 3，无第三方依赖
└── Readme.md
```

`send.py` 读取 PopClip 注入的 `POPCLIP_TEXT`、`POPCLIP_BROWSER_TITLE`、`POPCLIP_BROWSER_URL`、`POPCLIP_APP_NAME`、`POPCLIP_BUNDLE_IDENTIFIER`、`POPCLIP_MODIFIER_FLAGS` 以及各项 `POPCLIP_OPTION_*`，按来源判断是否合并硬换行、把正文转义为纯文本，组装成「列表项 + 子列表项」的 Markdown 后通过 stdin 交给：

```bash
SiYuan-Kernel block append --parent <文档或块ID> --file - -w <工作空间> -f json
```

按名称定位时用只读 SQL 查 `blocks` 表的 `id / hpath / box`；今日日记用 `dailynote create --notebook <ID>`；返回码 0 / 1 / 2 分别对应成功、运行失败、配置错误（PopClip 会自动弹出设置面板）。若 CLI 启动时写 `~/.config/siyuan/workspace.json` 遇到权限限制，脚本会自动改用临时 `--home-dir` 重试一次。
